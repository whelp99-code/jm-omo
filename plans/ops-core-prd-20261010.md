상태: **최종 후보본** (2026-10-10). 전체 합의 확정은 참여자별 명시 동의로만 잠금.

## 1. 문제
고객 장비 상태·장애·만료·담당·처리 결과가 메일·콘솔·사람 기억에 흩어져 있어, 어느 고객의 어떤 장비가 문제이고 누가 처리 중이며 실제로 해결됐는지 놓친다.

## 2. 결정 (D1–D12)
| ID | 결정 | 시험 |
|---|---|---|
| D1 | 제품 = 여러 고객 인프라를 맡은 운영자의 **장비 대장 + 사건 책임** 업무 공간. 관제 엔진(수집·그래프·경보)은 만들지 않는다. | T-SCOPE-1 |
| D2 | v1 사용자 = 내부 운영자(허용된 고객만 접근), 승인자(수동 변경의 승인 근거 연결, 원격 실행 없음). 고객 포털 없음. | T-AUTH-1..3 |
| D3 | v1 장비 = 읽기 전용(장비 설정을 바꾸지 않음). 배정·조치 기록은 플랫폼에 저장. | T-RO-1 |
| D4 | AI 없이도 운영 가능. AI는 기록 보조이며 판정자가 아니다. | T-AI-0 |
| D5 | v1 포함 = 고객·사업장·장비·서비스·담당·유지보수 범위 대장, 알림 1소스 수신, 사건 묶기, 배정, 사람 조치 기록, 재조회 검증, 기록 기반 고객별 최소 보고(운영자가 생성·검토). | T-FLOW-1 |
| D6 | v1 제외 = 관제 엔진, 장비 쓰기, 설정 백업·변경 비교, 만료 견적, AI 판정, 고객 포털, 원격 콘솔. 만료일은 대장 필드로만. | T-SCOPE-2 |
| D7 | 사건 상태 = 접수 → 처리 중 → 검증 대기(재조회 불가 시 사유·담당·다음 확인 시각) → 종료(해결 / 오탐 취소 / 중복 병합[대표 사건 링크, 실적 제외]). 검증 실패 → 처리 중. 고객 보고·회신 상태는 기술 복구 상태와 별도. 장비 상태 = 정상 / 이상 / 미확인. | T-STATE-1..6 |
| D8 | 이벤트 중복 키 = 고객 + 연결 소스 + 원본 이벤트 ID (없으면 대체 키 정의). 사건 묶기 키 = 고객 + 장비·서비스 + 장애 유형 + 발생 구간. 복구 뒤 재발은 새 사건. | T-DUP-1..4 |
| D9 | 고객 식별 = 플랫폼 고객 ID. CRM ID는 연결 필드. CRM 미등록·ID 변경·CRM 장애가 고객 격리에 영향 없음. | T-ISO-3 |
| D10 | 종료 기록 = 대상·검증 기준·시각·결과·근거. 검증 후 새 실패 이벤트가 들어오면 이전 근거로 종료 불가. | T-CLOSE-1..3 |
| D11 | 재사용 = **재사용할 기능에 해당하는 기준을 모두 통과**해야 한다(6기준: 식별·격리 / 근거·신선도 / 중복·순서 / 쓰기 경계 / 접속 / 비용). 관측 도구에 사건·승인·종료 기능이 없는 것은 읽기 연동의 탈락 사유가 아니다. 고객 격리·접속 보안 미충족이면 연결하지 않는다. 신선도·순서·누락 판별이 부족한 데이터는 한계를 표시하고 정상·해결 판정 근거로 쓰지 않는다. 사건·배정·종료 정본은 플랫폼. | T-REUSE-1..6 |
| D12 | 시험은 가상 고객 2곳 fixture로 먼저. 실고객·장비군·소스·동의·규모는 연결 전에 확정. P0은 비밀 값이 아니라 비밀 **참조** 설계까지이며, 사건 상태 기계 개발은 P0과 병행. | T-FIX-1 |

## 3. 핵심 흐름 (첫 시나리오)
백업 실패 알림 수신 → 중복 이벤트 제거(D8) → 사건 묶기 → 담당 배정 → 사람이 장비 조치, 플랫폼에 조치·승인 번호 기록 → 다음 백업 결과 재조회로 검증 → 종료(D10) → 고객별 보고에 반영.

## 4. 데이터 원칙
모든 사실에 출처 시스템·원본 ID·관측 시각·확인 상태. 관측 시각 없음 = 미확인. 고객별 격리, 감사 기록. 접속 비밀 값은 금고에만, 연결부는 참조만 받음. AI 대화·화면·공개 저장소에 비밀 값 없음. 고객 장비 기록은 공개 MCP 저장소 밖.

## 6. 인수 시험 (MVP 필수)
- T-ISO-1 검색·API·첨부·보고가 다른 고객 데이터를 읽지 못함 / T-ISO-2 같은 IP·같은 외부 알림 ID가 고객 사이에서 충돌하지 않음 / T-ISO-3 CRM 장애·ID 변경 시 격리 유지
- T-DUP-1 재전송으로 사건 증가 없음 / T-DUP-2 수집기 재시작으로 증가 없음 / T-DUP-3 복구 후 재발은 새 사건 / T-DUP-4 원본 ID 없는 소스의 대체 키
- T-STATE-1 늦은 이벤트가 최신 상태를 덮지 않음 / T-STATE-2 수집 지연 초과 시 '마지막 관측값 + 현재 미확인' / T-STATE-3 검증 실패 → 처리 중 / T-STATE-4 재조회 불가 → 검증 대기(사유·담당·다음 확인) / T-STATE-5 동시 배정·종료가 서로 덮지 않음 / T-STATE-6 고객 보고 상태 분리
- T-CLOSE-1 근거 누락 시 종료 불가 / T-CLOSE-2 검증 뒤 새 실패 시 종료 불가 / T-CLOSE-3 오탐 취소·중복 병합은 해결 실적 제외
- T-RECV-1 수신 저장 실패 시 성공 처리 금지, 재전송·누락 확인 경로
- T-AUTH-1..3 허용 고객만 / 승인자 원격 실행 없음 / 기능마다 정상·실패·권한 거부
- T-RO-1 장비 쓰기 경로 0

**합격선**: 정의된 시험 데이터와 장애 주입 시나리오에서 고객 혼합·서로 다른 장애의 오병합·추적되지 않은 수신 누락·근거 없는 해결 종료가 각각 0건. 원본 대조가 불가능한 구간은 미확인으로 표시.

## 7. 단계
- P0 접속 경로·금고·고객 격리 **설계**(비밀 참조까지) — 사건 상태 기계와 병행
- P1 대장 + 알림 1소스 + 사건 + 검증·종료 + 고객별 최소 보고 (가상 고객 2곳 fixture) + 산출물 「실고객 시험 연결 승인 및 운영 전 검증표」
- P2 월간 집계·보고 고도화·지표
- P3 진단 보조(Engineer MCP에서 남긴 도구; MCP 확정과 무관하게 시작 가능)
- P4 승인형 실행(시험 장비 → 고객)

## 8. 실고객 시험 연결 승인 및 운영 전 검증표 (2단계)
- 접속 전: 수집 동의·대상·읽기 권한·수집 항목·보관/삭제 기준 확정
- 승인된 시험 연결 후: API 응답·식별자 확인, 합의된 관측 구간에서 지연·연결 중단/재연결·원본 대조 가능 여부 검증
- 시험 연결과 운영 개시는 별도 승인. 미정 값이 남아 있으면 연결·운영 개시 조건 통과로 표시하지 않는다.
